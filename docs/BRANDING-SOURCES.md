Slice V0.5.16 / 16.10 treats the current approved visual identity as immutable input. This cleanup is dependency/ownership work only: **no redesign, recolor, recrop, artistic regeneration or fallback to historical cream branding.**

The version-looking filenames are retained intentionally. Renaming them would create wiring/cache churn without changing product value; canonical ownership is defined here and by CI rather than inferred from the filename suffix.

## Generated system assets

`favicon.ico` and the files under `icons/` are outputs, not visual masters. `scripts/generate-brand-assets.py` deterministically regenerates them from `branding/favicon-user-v058.b64` and separately locks the decoded source with SHA-256 `b0a52f01ae3679515abc10caf1db3a331a49ab57d85928ed3a007696a1f8eb3d`.

A branding PR must commit generated icon outputs together with any intentional source change; CI reruns the generator and rejects output drift.

## Guardrails

- `scripts/test-branding-sources.mjs` byte-locks all four canonical masters with Git blob hashes and verifies HTML/CSS/Service Worker/workflow wiring.
- `Generate brand assets` remains the only system-icon generator and must produce no uncommitted icon diff on a PR.
- New visual source files under `branding/` are not allowed without an explicit branding change; normal engineering must consume the four canonical masters above.
- Visual acceptance itself remains a product/device QA concern; passing this source guard proves identity bytes and wiring did not change, not that every installed-device cache has updated.
